### 1.2 PartyBot AI — Behavior Layer (v0.9.0) (docs/ARCHITECTURE.md:77-149)
Three-layer scored system replacing per-class if/else chains:
`SituationContext` snapshot once per tick → each `BotBehavior::Score(ctx)`
returns 0–100 × role weight → `BotBehaviorSet::RunBestBehavior()` sorts
descending, tries `Execute()` until one returns true (fallthrough on failure).
Documented at `docs/ARCHITECTURE.md:93-97`, restated as rules at
`.claude/rules/bots.md:9-14`. Source map (all under
`vmangos/src/game/PlayerBots/`):
- `PartyBotAI.cpp` dispatcher + pre-steps; `BotSituationContext.h/.cpp`;
  `BotBehavior.h/.cpp` (base + runner); `BotBehaviors_Shared.*`;
  `BotBehaviors_ClassUnique.*`; `BotSpellKit.*` (capability iface over the
  `m_spells` union — the *only* sanctioned way behaviours reference class
  spells, `.claude/rules/bots.md:49-59`); `BotRoleConfig.*` (factory + weights);
  `BotCombatEventBuffer.*` (encounter-learning ring buffer w/ DB persistence);
  `BotFormation.*`; `CombatBotBaseAI.*` (spell structs, population, healing).
  — `docs/ARCHITECTURE.md:81-91`.
- Pre-steps (unscored, every tick): pet attack, dispel check, Hunter
  Auto Shot, caster `AttackStart()` 25yd `MoveChase`
  (`docs/ARCHITECTURE.md:99-103`, `.claude/rules/bots.md:25-32`).
- Role weights e.g. Healing 0.3/1.5/0.0/0.0 (Tank/Healer/Melee/Ranged) —
  `docs/ARCHITECTURE.md:105-109`.
- Spec system: `LearnPremadeSpecForClass()` + 26 static `BotTalentBuild`
  arrays (9 classes × 2–3 specs) generated by
  `scripts/generate_talent_builds.py` from DBC; `player_premade_spell_template`
  now gear-only (`docs/ARCHITECTURE.md:134-141`, `.claude/rules/bots.md:131-144`).
- Design rationale & phased migration plan preserved in
  `docs/BOT_ARCHITECTURE_PROPOSAL.md` (problem: 12 files / ~9,300 lines of
  copy-pasted per-class chains, `:5`; 3-layer proposal `:15-44`; cons:
  scoring-tuning risk `:366`, debug traceability `:368`, per-tick scoring cost

### 1.3 Formation & movement (docs/ARCHITECTURE.md:151-193)
`BreadcrumbTrail` ring buffer (40 points, 1s sampling, >2yd threshold,
arc-length interpolation); role-ordered slots (Tank 2yd, Melee 4yd ±1,
Ranged 8yd ±1, Healer 10yd); two-layer lateral safety (navmesh
`Map::GetWalkHitPosition()` >3yd drift → collapse; 12yd hostile scan →
collapse); OOC `MovePoint` w/ 2yd dead-zone; combat ignores formation
(`!ctx.currentTarget` guard); kite flees backward along trail 15–30yd.
Movement-primitive semantics are codified in `.claude/rules/bots.md:65-71`
(`MovePoint` precise / `MoveChase` combat / `MoveFollow` legacy fallback;
MoveChase angle is a hint, not a constraint).

## 2. Production-phase constraints on a migration (CLAUDE.md:14-23)

Phase is explicitly `production` — "Real characters exist… Treat their data
as sacred" (`CLAUDE.md:16`). Four hard locks, each with a rules file:
1. **Append-only DB**: shipped migrations never edited; no `DROP TABLE`/
   `DROP COLUMN`/type-narrowing/rename/PK-change on player-data tables;
   idempotent SQL (`IF NOT EXISTS`, `ON DUPLICATE KEY`),
   `vmangos/sql/migrations/` via `make_migration.py`, migration+code in one
   commit (`CLAUDE.md:20`, `.claude/rules/database.md:24-73`). 1,038 migration
   files currently in that dir (incl. inherited upstream stream from 2021).
2. **Shape-stable JSON API**: ARCHITECTURE-listed dashboard endpoints are
   additive-only; rename/remove needs a versioned route (`CLAUDE.md:21`,
   `.claude/rules/python.md:72`).
3. **Additive bot behaviours**: new `BotBehavior` subclasses only; replacing/
   deleting a scored behaviour requires auditing its live `Score()` role
   (`CLAUDE.md:22`, `.claude/rules/bots.md:21`).
4. **Locked save formats**: character inventory, item instance, guild roster;
   additions via guarded migrations (`CLAUDE.md:23`).
Plus phase-independent rules: secret hygiene (`.env`/`*.conf` gitignored,
gitleaks hard-fail — `CLAUDE.md:29`, `.claude/rules/security.md:27-42`),
SRP6 auth not to be re-rolled, 16-char client password cap
(`security.md:46-49`), packet shapes immutable (1.12.1 client binary —
`.claude/rules/wow-domain.md:34-39`), world tick single-threaded, no
exceptions across it (`.claude/rules/cpp.md:45-65`).

### Commit/hook/release discipline
- Conventional Commits 1.0, scopes `vmangos|dashboard|discord-bot|scripts|
  db|bots|docs`, subject ≤72 chars imperative lowercase
  (`.claude/rules/commits.md:31-51`); enforced by pure-bash
  `.githooks/commit-msg` (TYPE_RE/SCOPE_RE verified in file head).
- `.githooks/pre-commit`: gitleaks staged scan (hard-fail if gitleaks absent),
  `clang-format --dry-run -Werror` on staged C++, `ruff check` +
  `ruff format --check` on staged Python; no C++ build (CI's job) —
  file header lines 7–13, `CLAUDE.md:60`. Wired via
  `git config core.hooksPath .githooks` (`CLAUDE.md:54-58`).
- Release: `scripts/release.sh` auto-detects bump from commit subjects since
  last tag (`feat`→minor `:61-62`, `fix`→patch `:63-64`, else no release),
  annotated tag, `git push origin main --tags`, `gh release create`, Discord
  post via `discord-bot/post_patch_notes.py` (`:115-126`). `--dry-run` at
  `:109-112`. **No major-bump path in the script** — commits.md:87 says major
  only via explicit `release.sh major`, but the script's arg parser
  (`:28-34`) accepts only `patch|minor|--dry-run`: doc/script drift.
- Tags today: `v0.4, v0.5.0 … v0.9.0` (10 tags, latest v0.9.0). 78 commits
  total; last-30 shape mostly conventional (`feat/fix/docs(vmangos): …`) but

  began at `dbbd226 chore: bootstrap CLAUDE.md, rules, hooks, and CI`.
- "Tested" = manual in-game smoke test (e.g. Deadmines 5-man clear) + PR

- Definition of done: clean compile, clang-format/ruff gates, no edited

## 4. Design lessons / gotchas a Rust rewrite must preserve

From `docs/ARCHITECTURE.md:121-128,186-191` + `.claude/rules/bots.md` +
`cpp.md`/`wow-domain.md` (each is a shipped-and-reverted bug per bots.md:3):
1. **`Score()` must check preconditions** — score>0 + always-failing
   `Execute()` starves lower behaviours; "single most common bug"
   (bots.md:19, clean-code.md:53). In Rust: make Score/Execute one
   fallible `try_act()` or keep the invariant as a trait contract + debug
   assertion; note runner's fixed `Candidate[32]` cap (BotBehavior.cpp:27)
   silently drops behaviours past 32 — don't replicate.
2. **Free actions are pre-steps, never scored** (bots.md:23-32).
3. **`time_t fireTime`, never ms countdowns**, for anything deferred on the
   60s chat tick (bots.md:34-46) — commit `f84efe1 fix(vmangos): chain/debate
   messages all firing at once` is the scar. In Rust: store absolute
   `Instant`/epoch deadlines in the scheduler, not remaining-durations.
4. **Formation must not fire in combat** (`!ctx.currentTarget` guard,
   bots.md:73-75); two-layer lateral safety (navmesh *and* aggro scan —
   walkability ≠ safety, bots.md:77-82); `POINT_MOTION_TYPE` excluded from
   needFollow; trail cleared on >100yd teleport (bots.md:86-88).
5. **`MoveChase` angle is a hint; `MovePoint` for precise spots** (rogue
   behind-target) (bots.md:67-71); stealth guards in `AttackStart`/follow
   (bots.md:112-115).
6. **`AttackStop()` clears `m_attacking`** — never before
   `EvaluateSituation()`; casters need it every tick to not melee-walk
   (bots.md:108-110). Order-of-operations invariant for the tick pipeline.
7. **Never set legacy flags (`m_isBuffing`) from behaviours** (bots.md:166);
   **`.partyrole` must set `m_resetSpellData=true`** to rebuild the set
   (bots.md:100).
8. **Tank detection priority + explicit-role gate**: human w/ explicit
   non-tank role skips shield/Bear heuristics (bots.md:92-98).
9. **Class rules with mechanical teeth**: PW:S never on warrior tank >15% HP
   (threat+rage), all 3 sites agree (bots.md:117-119); one curse/warlock/
   target, Tongues>Elements>Shadow>Agony, Recklessness+Fear banned
   (bots.md:121-125); Voidwalker excluded when tank present (bots.md:123);
   healer 12–18yd follow + tank-target fallback (bots.md:104-106).
10. **BotSpellKit-only spell access**; wire new capabilities for *all*
    classes (bots.md:47-59). Rust analogue: capability trait per class,
    behaviours generic over it — preserves the anti-per-class-polymorphism
    lesson (clean-code.md:51,55).
11. **Generated talent arrays**: regenerate via script, never hand-edit
    (bots.md:140,168) — keep the generator (or port it) as source of truth.
12. **Platform invariants**: single-threaded world tick, no panics/exceptions
    across it, GUIDs (values) not pointers across ticks, async DB callbacks
    must not touch game objects (cpp.md:43,47,64-65); crowd bots must be full
    `Player` entities for `PLAYER_VISIBLE_ITEM` (ARCHITECTURE.md:325);
    enchant-via-trade-window loops → apply directly (ARCHITECTURE.md:221).

## 5. Rust-migration implications (this scope only)

- **The docs are the spec, but verify before porting**: 3/5 spot-checked
  claims exact, 2 stale in *counts/tables* (behaviour counts, API table,
  version). Behavioural *semantics* docs (scoring, formation, gotchas)
  matched code everywhere checked — port semantics from docs+rules, port
  inventories (endpoint lists, behaviour catalogues, GUID/account maps) from
  code/DB, not from ARCHITECTURE.md tables.
- **Compatibility surface is contractual, not incidental**: MySQL schemas
  (append-only, locked save formats), dashboard JSON shapes, 1.12.1 wire
  packets/opcodes, SRP6, `.conf`/`.env` keys, in-game command surface
  (`.partybot`, `.partyrole`, `.guildraid` + SEC levels), and the
  account-ID bot taxonomy must survive any rewrite byte-for-byte at the
  boundary. A Rust core can replace internals only behind these contracts
  while production data lives.
- **Process must be re-homed, not dropped**: conventional-commit → semver
  release derivation, gitleaks hard-fail, format gates (clang-format/ruff →
  rustfmt/clippy analogues), append-only migration tooling, and the
  smoke-test-as-evidence norm are load-bearing for a solo production server.
- **`vmangos-rs/` already exists** in-tree (contains only `target/` at time
  of inspection) — migration scaffolding has begun; this report does not
  assess its contents (out of scope).
- Docs precedence rule worth keeping: CLAUDE.md wins for *rules*,
  ARCHITECTURE.md for *how things work today* (CLAUDE.md:50) — a Rust guide
  should state which of its claims are rules vs current-state, since the
  latter rot (as §3 shows).
