- [x] Detour FFI spike — **feasible, green** (no fallback needed).
      New crate `mangos-detour`: `build.rs` compiles the vendored,
      TrinityCore-patched Detour sources in place
      (`vmangos/dep/recastnavigation/Detour`, `DT_POLYREF64`
      12/21/31 split; override `MANGOS_DETOUR_SRC`) plus a small C
      shim (`shim/detour_shim.cpp`) — Rust never mirrors C++ class
      layouts (`dtQueryFilter` is built inside the shim). This is
      the workspace's one sanctioned-unsafe crate: `unsafe_code =
      deny` crate-wide with `#[allow(unsafe_code)]` only on the
      `ffi` module; the public API is safe and mirrors `MoveMap`
      loading (params file, `MmapTileHeader` validation, tile
      ownership via `DT_TILE_FREE_DATA`) and `PathFinder` policy
      (`FindWalkPoly` extents/above-check, `createFilter` /
      `FillTargetAllowedFlags` include words, XYZ↔YZX at the
      boundary).
      Evidence: goldens from an independent C++ harness
      (`vmangos-rs/scripts/detour_oracle.cpp`, direct Detour API,
      not the shim) over 5 production map-000 tiles — 60
      nearest-poly probes and 8 full path queries (poly corridors
      + straight-path points) match **bit-for-bit** through the
      FFI (`tests/production_mmap.rs`, env `MANGOS_MMAPS_DIR`,
      wired into `ci.sh`). Both sides compile the vendored
      sources with `-ffp-contract=off` so goldens don't depend on
      FMA contraction. Notes: poly-refs depend on tile load order
      (both sides load the golden order; production loads lazily
      by grid, so Phase 3 comparisons should key on geometry);
      the crate makes a C++ toolchain a workspace build
      requirement; full `PathInfo::calculate` (shortcuts,
      swim/fly, smoothing) remains Phase 3 world work on this
      surface.
